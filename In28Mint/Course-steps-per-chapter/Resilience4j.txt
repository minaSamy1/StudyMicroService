---------------------------------------------- circuit breaker -------------------

usage : 
    a circuit breaker is used to prevent a system from repeatedly trying to call a failing service.
	
Key Benefits:
	Resilience: Protects your application from failures in other services.
	Fault Tolerance: Allows the system to fail gracefully instead of failing completely.
	Fallback Mechanisms: You can define fallback logic if the service is down.
	Prevent Service Overload: Prevents overloading a failing service with additional requests.
	
Example Scenario:
  Imagine you have a microservice that calls an external payment service.
  If the payment service is down, you don't want to keep trying and cause further delays or failures.
  The circuit breaker will "open" after several failures and return a fallback response,
  preventing your app from waiting endlessly for a failing service.
  
 Common Libraries for Circuit Breakers:  ( Resilience4j , Hystrix )
    @CircuitBreaker(name = "default", fallbackMethod = "hardcodedResponse")
		public String sampleApi() {
			logger.info("Sample api call received");
			ResponseEntity<String> forEntity = new RestTemplate().getForEntity("http://localhost:8080/some-dummy-url",
					String.class);
			return forEntity.getBody();
		}
  public String hardcodedresponse(Exception e)
    {
        return "Fallback-Response";
    }

summary:
  Retry helps handle temporary failures by trying again, 
  whereas Circuit Breaker stops making requests when a failure threshold is crossed
  , preventing overloading of a failing service.
  
	--------------------------------------RateLimiting ---------------------------------
	
The goal of a RateLimiter is to prevent overloading a service by controlling the flow of requests, 
 ensuring that they don't exceed a certain threshold over a specific time period.

	--------------------------------------Bulkhead ---------------------------------
usage :
 This limits the number of concurrent requests to x number. If there are more than 5 requests trying to access this endpoint at the same time, the 6th request will be either queued or rejected (depending on your configuration).
You can also configure additional parameters, like queueCapacity, and maxWaitDuration to control the behavior of excess requests.

application.properities 
   
## Bulkhead Configuration
resilience4j.bulkhead.instances.default.maxConcurrentCalls=4
resilience4j.bulkhead.instances.default.queueCapacity=0

   @GetMapping("/sample-api-rate")

        return "sample-api";
